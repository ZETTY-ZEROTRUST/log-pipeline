# STAR 작업 기록 — log-pipeline

이 저장소에서 진행하는 작업의 **착수 전 설계와 결과**를 STAR 흐름으로 남긴다.

## 작성 규칙

1. **착수 전에 반드시 작성한다.** S·T·A(계획)를 채우고 상태를 `계획`으로 둔 채 먼저 커밋한다. 문서가 없는 작업은 시작하지 않는다.
2. 진행 중 생긴 문제와 방향 전환은 A의 **시행착오**에 날짜와 함께 추가한다. 처음 계획은 지우지 않는다.
3. R에는 **실측값만** 쓴다. 환경·데이터 규모·부하 조건·반복 횟수·명령을 함께 기록한다. 측정 전에는 `미측정`으로 둔다.
4. 근거는 `파일:라인`, 명령과 exit code, 측정 산출물 경로로 연결한다. 토큰·키·자격증명 원문은 쓰지 않는다.
5. 자소서 한 줄은 R이 확정된 뒤에만 쓴다.

| 질문 | STAR 항목 |
|---|---|
| 문제 발생? (무엇이 어떤 리스크인가) | **S** Situation |
| 왜? (무엇을 달성해야 하나, 성공 기준) | **T** Task |
| 어떻게? (선택한 기술과 대안, 이유) | **A** Action |
| 어떻게 개선했나? (전/후 수치) | **R** Result |

## 공격 → 개선 사이클 기록

이 프로젝트는 **구현 → 로컬 lab에서 시나리오대로 공격 → 취약점 확인 → 개선 → 같은 시나리오로 재공격**을 반복한다. 사이클마다 문서 하나를 남긴다.

| 단계 | 기록 위치 |
|---|---|
| 공격 성공(취약) 증거: run_id, 시나리오 버전, 응답 코드·건수 | S |
| 막아야 하는 이유와 차단 기준 | T |
| 수정 내용과 대안 | A |
| 재공격 결과(차단율, 정상 요청 성공률), 성능 영향 | R |

공격은 `attack-simulation`의 승인된 로컬 대상과 모의 계정에만 실행한다. 토큰·키 원문은 기록하지 않는다.

```markdown
# <ID> <제목>

- 상태: 계획 | 진행 | 완료 | 보류
- 연결: Jira <ID> · 부하 실험 <L-n> · 관련 문서
- 작성/갱신: YYYY-MM-DD

## S — 문제 발생 (Situation)
## T — 왜 / 목표 (Task)
## A — 어떻게 (Action)
### 계획
### 검토한 대안과 선택 이유
### 시행착오
## R — 개선 결과 (Result)
## 자소서 한 줄 (R 확정 후)
```
